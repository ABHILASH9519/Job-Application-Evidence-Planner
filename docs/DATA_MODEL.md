# Data Model

This document defines the browser-local record model used by the current implementation.

## Application

| Field | Meaning | Initial rule |
| --- | --- | --- |
| id | Stable record identifier | Generated when created |
| company | Employer or organization | Required, trimmed text |
| role | Position title | Required, trimmed text |
| jobUrl | Original job posting | Optional valid HTTP(S) URL |
| appliedAt | Date application was submitted | Optional date value |
| stage | Current pipeline position | saved, applied, assessment, interview, offer, rejected; defaults to saved |
| followUpAt | Date for the next follow-up | Optional date value; overdue dates are highlighted in the workspace |
| nextStep | Next action or follow-up | Optional text |
| notes | Applicant's private notes | Optional text |
| createdAt | Record creation time | Generated by the app |
| updatedAt | Most recent edit time | Updated on mutation |

## Evidence item

| Field | Meaning | Initial rule |
| --- | --- | --- |
| id | Stable record identifier | Generated when created |
| applicationId | Parent application reference | Optional only when supporting general experience; otherwise must resolve |
| requirement | Requirement from the role | Required, trimmed text |
| evidenceTitle | Project, internship, coursework, or experience | Required, trimmed text |
| evidenceUrl | Supporting link | Optional valid HTTP(S) URL |
| contribution | What the applicant personally did | Applicant-authored text |
| context | Limitations, scope, or relevant qualification | Applicant-authored text |
| status | Evidence readiness | planned, in_progress, completed |
| createdAt | Record creation time | Generated by the app |
| updatedAt | Most recent edit time | Updated on mutation |

## Relationships and integrity

- An application can have zero or many evidence items.
- Evidence records should not silently point to a deleted application. The implementation preserves associated evidence as unlinked evidence when an application is deleted.
- Application stage and evidence status values must be validated against their allowed sets.
- Legacy backups without stage or follow-up date fields are accepted; imported applications default to saved with no follow-up date.
- Dates should be serialized consistently in JSON exports.
- Export should include contribution and context, not only titles and URLs.

## Privacy

Treat all application and evidence content as personal data. Keep it in browser-local storage in the initial release. Do not transmit it to a remote service without an explicit, documented product change and user consent.
